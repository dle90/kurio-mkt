How to read. Scan a row left→right: a code that turns and stays green is paying back. The right-hand columns are the most recent cohorts — their revenue is still arriving (a registration takes days–weeks to become an order), so amber on the right usually means "not matured yet", not "failed". Judge ROAS on the older (left) columns; judge recent days on spend·regs.

Why codes. Orders carry the customer's ads_code → code, never a campaign id, so revenue & ROAS exist only at the code level. The TOTAL · ad-coded row is the true daily total of ads-code-attributed activity — it includes Engage/brand spend that maps to no code, so the per-code rows sum to slightly less.

Reg vs CRM. The reg counter throughout this view is ad-coded only — customers whose Getfly account carries an ads_code. The dashed CRM reg / day row below the TOTAL shows every Getfly registration that day across all sources (ad + organic + renewal + IKMC scholarship + app self-serve + ad-without-code-captured). The +N small number is the gap — what the team sees in CRM that this view's ad-coded totals exclude.

Method. Daily spend from campaign insights (K2+3+5, live), mapped to code via ad-level meta_spend_monthly.json. Revenue = approved sale_orders.real_amount joined via the customer's Getfly ads_code → code; LTD = all booking days. Rebuild: node src/dashboard/cohort_drilldown.js (DAYS=30 to widen).
